# Метрики производительности NeuralTower

Перечень метрик для сравнительного анализа программных конфигураций (движки инференса, квантование, спекулятивное декодирование, виртуализация памяти) при фиксированном аппаратном составе.

## 1. Метрики эффективности генерации на уровне языковой модели

* **Время до первого токена (TTFT)** — секунды/миллисекунды. Интервал от получения запроса до генерации первого токена. Отражает скорость фазы Prefill, показатель эффективности Chunked Prefill.

* **Задержка между токенами (ITL)** — миллисекунды. Среднее время генерации каждого токена после первого. Измеряет скорость фазы Decode, позволяет оценить прирост от спекулятивного декодирования (MTP, EAGLE, Medusa).

* **Скорость генерации на одну последовательность** — токены/сек (t/s). Количество токенов для одного пользователя за секунду. Рассчитывается как отношение выведенных токенов к времени генерации без Prefill.

* **Суммарная пропускная способность** — токены/сек по всем потокам. Совокупный объём при параллельной работе нескольких агентов. Критерий эффективности Continuous Batching.

## 2. Метрики подсистемы кэширования контекста

* **Попадание в кэш контекста (Hit Rate)** — %. Доля запросов, для которых KV-кэш найден в памяти и переиспользован без пересчёта. Измеряется отдельно для VRAM, RAM и NVMe (Intel DC P4510).

* **Промах кэша (Miss Rate)** — %. Доля запросов с полным пересчётом из-за вытеснения данных (LRU).

* **Задержка извлечения холодного контекста** — секунды. Время чтения, деквантования и загрузки KV-кэша из иерархических слоёв (NVMe Intel DC P4510 → RAM → VRAM) при повторном обращении к обработанному контексту.

* **Скорость вытеснения кэша** — МБ/с, сессии/мин. Интенсивность удаления старых файлов контекста при достижении лимитов ёмкости. Показывает накладные расходы ОС на файловые операции.

## 3. Метрики утилизации аппаратных ресурсов на уровне телеметрии железа

* **Загрузка GPU (Вычисления)** — %. Утилизация тензорных и потоковых ядер. Падение ниже 80% при обработке контекста указывает на простои в конвейере или задержки ввода-вывода.

* **Распределение VRAM** — ГБ. Потребление HBM2 на каждой карте: статическая область (веса модели) и динамическая (кэш, активации). Используется для поиска утечек памяти при подборе размера фрагмента.

* **Пропускная способность NVLink** — ГБ/с. Скорость обмена между GPU внутри мезонина. Интенсивность операций AllReduce при тензорном параллелизме (`TP=2`).

* **Пропускная способность PCIe (через PLX)** — ГБ/с. Данные через коммутаторы PLX. Нагрузка в двух точках: передача тензоров между PP-стадиями (`PP=2`) и сброс/чтение кэша на Intel DC P4510 NVMe.

* **Потребление мощности** — Вт. Суммарная мощность сервера и отдельных GPU/CPU.

* **Температура GPU / CPU** — °C. Текущая температура вычислительных устройств.

* **Глубина очереди запросов** — штуки. Число запросов в очереди планировщика.

## 4. Интегральные системные метрики на уровне сквозного анализа

* **Стабильность отклика (Latency Jitter)** — коэффициент вариации / стандартное отклонение. Разброс времени генерации на идентичные запросы. Высокий показатель указывает на проблемы контроллеров памяти или конфликты блокировок при обращении к накопителю.

* **Энергоэффективность (Performance-per-Watt)** — токены/Вт·ч. Интегральный показатель экономичности конфигурации. При жёстких ограничениях по питанию оптимизация пакетирования и фрагментов должна максимизировать утилизацию ядер в рамках TDP.
