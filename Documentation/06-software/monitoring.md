# Мониторинг и GPU Watchdog

## 1. Настройка промышленной панели мониторинга Grafana

Для обеспечения детального контроля над состоянием четырех ускорителей Tesla V100 используется эталонный шаблон мониторинга. Поскольку стандартные настройки рассчитаны на серверные стойки, требуется ручная адаптация файла под параметры настольного узла NeuralTower.

### 1.1. Загрузка шаблона

Официальный файл конфигурации необходимо загрузить с портала Grafana Dashboards:
* **Источник:** [NVIDIA DCGM Exporter Dashboard (ID: 12239)](https://grafana.com)
* **Метод:** Нажмите кнопку «Download JSON» и сохраните файл под именем `grafana_dashboard.json` в текущую директорию со скриптами.

### 1.2. Ручные правки конфигурации

Откройте загруженный файл `grafana_dashboard.json` в любом текстовом редакторе и внесите следующие изменения:

* **Наименование проекта:**
  Найдите строку `"title": "NVIDIA DCGM Exporter Dashboard"` и замените её на `"title": "NeuralTower Operational Center"`.
* **Частота опроса:**
  Для мгновенной фиксации скачков температуры при нагрузке в 1.4 кВт найдите параметр `"refresh": "1m"` и измените его на `"refresh": "5s"`.
* **Идентификатор (UID):**
  Найдите строку `"uid": "..."` и замените её значение на `"uid": "neuraltower_full"`. Это необходимо для корректной работы системы автоматического импорта (Provisioning).
* **Коррекция порогов (Thresholds):**
  Найдите секции, отвечающие за температуру (GPU Temp), и установите критический порог (red) на значение `75`. При 80 °C происходит троттлинг GPU, поэтому порог 75 °C обеспечивает запас для реактивных действий до начала троттлинга. Порог согласован со скриптом мониторинга `monitor.sh`.

### 1.3. Применение изменений

После сохранения правок убедитесь, что в файле `docker-compose.yaml` прописан путь к этому JSON-файлу в секции `volumes` для контейнера Grafana. При следующем запуске команды `docker-compose up -d` панель мониторинга будет импортирована автоматически со всеми внесёнными изменениями.

## 2. Инженерная записка: GPU Watchdog

### 2.1. Проблема

В системе используются два блока питания Chieftec Polaris Pro 1300W. Ведомый БП питает мезонин 2 (GPU 2 и 3) и помпы системы жидкостного охлаждения. Если Add2PSU не сработал или ведомый БП вышел из строя, GPU 2 и 3 станут недоступны, а помпы не запустятся. Без защиты это приводит к:

- Запуску vLLM/SGLang с неполной топологией GPU (конвейер PP=2 не соберётся, модели класса 70B+ не запустятся);
- Перегреву GPU на мезонине 1 из-за остановки циркуляции теплоносителя.

### 2.2. Решение

Два уровня защиты, встроенные в docker-compose.

#### Startup Check (`gpu_watchdog.sh`)

Запускается первым сервисом через контейнер `gpu-check`. Выполняет запрос к `nvidia-smi` и ждёт появления всех четырёх GPU — до пяти попыток с интервалом в 30 секунд. Если обнаружено меньше четырёх GPU, скрипт завершается с кодом 1, и vLLM/SGLang не стартует. Полный лог пишется в `/var/log/neural_tower_gpu_check.log`.

#### Watchdog (`gpu_watchdog_loop.sh`)

Фоновый контейнер `gpu-watchdog`. Каждые 10 секунд проверяет количество доступных GPU. При потере любого из них:

- логирование пропавших GPU и дампа `dmesg`;
- остановка контейнеров с рабочими нагрузками (`docker stop` для vLLM и SGLang);
- однократный shutdown — маркер-файл предотвращает повторное срабатывание.

### 2.3. Логи

| Файл | Описание |
| --- | --- |
| `/var/log/neural_tower_gpu_check.log` | Startup Check: результат и причина блокировки запуска |
| `/var/log/neural_tower_gpu_watchdog.log` | Watchdog: события, остановка контейнеров, состояние GPU |

### 2.4. Ограничения

Watchdog останавливает контейнеры с рабочими нагрузками, но не обесточивает систему. После срабатывания требуется физическая диагностика и перезагрузка.
