# Оптимизация среды NeuralTower на базе Gentoo Linux

Для реализации максимального потенциала связки Xeon E5-2687W v4 и четырех ускорителей Tesla V100 выбрана операционная система Gentoo Linux. Это позволяет использовать преимущества новейших инструкций компилятора и специфических оптимизаций ядра для работы с тензорными вычислениями и высокоскоростным обменом данными по шине PCIe 3.0.

Документ объединяет настройки для двух инференс-движков: **vLLM** (основной) и **SGLang** (альтернативный). Различия отмечены явно.

## 1. Настройка глобальных параметров сборки (make.conf)

Ключевым преимуществом Gentoo является возможность пересборки всей системы с флагами оптимизации под архитектуру Broadwell. Это критично для библиотек препроцессинга данных и драйверов, где важна минимальная задержка.

Основные параметры в `/etc/portage/make.conf`:

*   `COMMON_FLAGS="-O3 -march=broadwell -pipe -flto=auto"` — агрессивная оптимизация и межмодульная оптимизация времени линковки (LTO) для всех системных компонентов. Для SGLang это критически важно для асинхронного планировщика на базе Triton и uvloop при работе с длинным контекстом.
*   `USE="cuda nccl cudnn mpi tensorrt openmp opencl pcie-p2p numa -X -wayland -gui -dist-kernel"` — активация поддержки CUDA 12.8, протоколов прямого обмена данными между GPU и оптимизации NUMA.
*   `USE="cuda nccl cudnn mpi tensorrt openmp opencl pcie-p2p numa uvloop -X -wayland -gui -dist-kernel"` — **SGLang-специфично:** добавлен флаг `uvloop` для асинхронного движка событий SGLang.
*   `PYTHON_TARGETS="python3_12"` — Python 3.12 требуется для совместимости с готовыми wheel-пакетами 1Cat-vLLM. Для SGLang — стабильная версия интерпретатора для работы с буферами памяти (`memoryview`). При использовании Python 3.13 необходимо собирать vLLM из исходников (см. [world-build.md](./world-build.md), Конфигурация B).
*   `VIDEO_CARDS="nvidia"` — сборка драйверов ветки 580.x или новее с поддержкой Volta (sm_70).

## 2. Конфигурация ядра Linux 6.x+

Современные ядра Linux получили значительные улучшения в планировщике задач и подсистеме памяти, что критично для работы vLLM и SGLang.

### 2.1. Общие опции (vLLM и SGLang)

Необходимые опции при сборке:

*   `PCI_P2PDMA` / `CONFIG_PCI_P2PDMA=y` — поддержка прямого доступа к памяти между устройствами на шине PCIe (Peer-to-Peer). Для SGLang: прямой доступ через коммутаторы PLX без транзита через CPU.
*   `NVME_CORE` — основа поддержки NVMe накопителей.
*   `NVME_MULTIPATH` — для оптимизации работы с NVMe-накопителем, используемым в качестве swap-пространства.
*   `HAVE_ARCH_HUGE_VMAP` — поддержка больших страниц памяти для ускорения работы CUDA-контекстов.
*   `NVIDIA_GDRV` — если используется модуль прямого доступа к памяти видеокарт.

### 2.2. SGLang-специфичные опции ядра

Иерархическая структура KV-кэша SGLang (GPU HBM → CPU RAM → NVMe SSD Intel DC P4510) требует дополнительной настройки виртуальной памяти ядра для исключения задержек ввода-вывода.

*   `CONFIG_NUMA=y` и `CONFIG_X86_PKG_MULTICORE_IPS=y` — адресация памяти четырехканального режима ECC DDR4 RDIMM с учетом топологии процессора.
*   `CONFIG_TRANSPARENT_HUGEPAGE=y` и `CONFIG_TRANSPARENT_HUGEPAGE_ALWAYS=y` — выделение памяти страницами по 2 МБ вместо 4 КБ. Снижает количество промахов TLB при обращении к страницам RadixAttention.
*   `CONFIG_CMA=y` (Contiguous Memory Allocator) — непрерывные физические области RAM для ускорения DMA-передачи активаций между мезонинами на стыках PP-стадий (`PP=2`).
*   `CONFIG_IOSCHED_NONE=y` или `CONFIG_BLK_DEV_THROTTLING=y` — отключение планировщиков ввода-вывода для NVMe SSD (Intel DC P4510). Режим `none` (или `kyber`) сохраняет микросекундную латентность при случайном чтении файлов кэша.

## 3. Системные параметры виртуальной памяти (sysctl.conf)

Для предотвращения сброса страниц памяти на системный диск в `/etc/sysctl.conf` внесены следующие директивы:

```ini
# Полностью минимизируем агрессивность использования стандартного Linux Swap
vm.swappiness = 1

# Оптимизируем удержание кэша страниц префиксов в оперативной памяти хоста
vm.vfs_cache_pressure = 50

# Резервирование 48 ГБ под страницы памяти (2MB)
vm.nr_hugepages = 24576
# Резервирование 160 ГБ под страницы памяти (2MB)
#vm.nr_hugepages = 81920
# Резервирование 400 ГБ под страницы памяти (2MB)
#vm.nr_hugepages = 204800
```

## 4. Формирование программного стека ML

Стек машинного обучения в Gentoo требует согласованности следующих версий пакетов:

1.  **Драйверы и тулкит:** `x11-drivers/nvidia-drivers` версии 580+ (стабильная поддержка sm_70) и `dev-util/nvidia-cuda-toolkit:12`. Для SGLang: установка в режиме без графической оболочки (без X-сервера) гарантирует монопольное владение CUDA-драйвера индексами устройств `0,1,2,3`.
2.  **Библиотеки глубокого обучения:** `sci-libs/cudnn:9.x` и `sci-libs/nccl:2.20+` с поддержкой аппаратного ускорения внутри мезонинов. Для SGLang: сборка NCCL с флагом `pcie-p2p` изолирует трафик AllReduce тензорного параллелизма (`TP=2`) внутри NVLink-линий мезонинов. Triton JIT-ядра SGLang требуют дополнительных настроек NUMA-привязки.
3.  **Контейнеризация:** `app-containers/docker` с поддержкой `nvidia-container-toolkit`. Для SGLang: обеспечивает проброс скомпилированных Triton-ядер из хост-системы в изолированное окружение SGLang.

## 5. Обновление и запуск системы

Для приведения системы в соответствие с выбранными флагами выполняется полная пересборка мира:

```bash
emerge --ask --verbose --update --deep --newuse @world
```

Запуск контейнера SGLang выполняется с распределением памяти NUMA для равномерной нагрузки по всем модулям:

```bash
numactl --interleave=all docker compose up -d
```
