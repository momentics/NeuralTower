# Оптимизация среды NeuralTower на базе Gentoo Linux под архитектуру SGLang

Для реализации максимального потенциала связки Xeon E5-2687W v4 и четырех ускорителей Tesla V100 (SXM2) в архитектуре SGLang выбрана операционная система Gentoo Linux. Профиль оптимизирован под трехуровневое кэширование SGLang HiCache, алгоритмы переиспользования контекста RadixAttention и спекулятивное декодирование EAGLE в гибридной топологии NVLink и PCIe 3.0.

## 1. Настройка глобальных параметров сборки (make.conf)

Пересборка системного окружения с флагами оптимизации под микроархитектуру Broadwell минимизирует накладные расходы на уровне системных вызовов. Это критически важно для асинхронного планировщика SGLang на базе Triton и uvloop при работе с длинным контекстом.

Основные параметры в `/etc/portage/make.conf`:

*   `COMMON_FLAGS="-O3 -march=broadwell -pipe -flto=auto"` - агрессивная оптимизация и межмодульная оптимизация линковки (LTO) для максимальной пропускной способности памяти.
*   `USE="cuda nccl cudnn mpi tensorrt openmp opencl pcie-p2p numa uvloop -X -wayland -gui -dist-kernel"` - поддержка параллельных вычислений, прямого обмена между GPU (P2P), оптимизации NUMA-узлов и асинхронного движка событий.
*   `PYTHON_TARGETS="python3_12"` - стабильная версия интерпретатора для работы с буферами памяти (`memoryview`).
*   `VIDEO_CARDS="nvidia"` - драйвер ветки 580.x или новее с поддержкой Volta (sm_70).

## 2. Низкоуровневая конфигурация ядра Linux 6.x+

Иерархическая структура KV-кэша SGLang (GPU HBM → CPU RAM → NVMe SSD Intel DC P4510) требует настройки виртуальной памяти ядра для исключения задержек ввода-вывода.

Необходимые опции при компиляции ядра (`make menuconfig`):

*   `CONFIG_PCI_P2PDMA=y` - прямой доступ к памяти между устройствами PCIe через коммутаторы PLX без транзита через CPU.
*   `CONFIG_NUMA=y` и `CONFIG_X86_PKG_MULTICORE_IPS=y` - адресация памяти четырехканального режима ECC DDR4 RDIMM с учетом топологии процессора.
*   `CONFIG_TRANSPARENT_HUGEPAGE=y` и `CONFIG_TRANSPARENT_HUGEPAGE_ALWAYS=y` - выделение памяти страницами по 2 МБ вместо 4 КБ. Снижает количество промахов TLB при обращении к страницам RadixAttention.
*   `CONFIG_CMA=y` (Contiguous Memory Allocator) - непрерывные физические области RAM для ускорения DMA-передачи активаций между мезонинами на стыках PP-стадий (`PP=2`).
*   `CONFIG_IOSCHED_NONE=y` или `CONFIG_BLK_DEV_THROTTLING=y` - отключение планировщиков ввода-вывода для NVMe SSD (Intel DC P4510). Режим `none` (или `kyber`) сохраняет микросекундную латентность при случайном чтении файлов кэша.

## 3. Системные параметры виртуальной памяти (sysctl.conf)

Для предотвращения сброса страниц памяти на системный диск в `/etc/sysctl.conf` внесены следующие директивы:

```ini
# Полностью минимизируем агрессивность использования стандартного Linux Swap
vm.swappiness = 1

# Оптимизируем удержание кэша страниц префиксов в оперативной памяти хоста
vm.vfs_cache_pressure = 50

# Резервирование 48 ГБ под страницы памяти (2MB)
vm.nr_hugepages = 24576
# Резервирование 160 ГБ под страницы памяти (2MB)
#vm.nr_hugepages = 81920
# Резервирование 400 ГБ под страницы памяти (2MB)
#vm.nr_hugepages = 204800

```

## 4. Формирование программного стека машинного обучения

Изоляция вычислительных контекстов реализуется через согласованность следующих пакетов:

1.  **Драйверы и инструментарий:** `x11-drivers/nvidia-drivers` (580+) и `dev-util/nvidia-cuda-toolkit:12`. Установка в режиме без графической оболочки (без X-сервера) гарантирует монопольное владение CUDA-драйвера индексами устройств `0,1,2,3`.
2.  **Библиотеки аппаратного ускорения:** `sci-libs/cudnn:9.x` и `sci-libs/nccl:2.20+`. Сборка NCCL с флагом `pcie-p2p` изолирует трафик AllReduce тензорного параллелизма (`TP=2`) внутри NVLink-линий мезонинов. Triton JIT-ядра SGLang требуют дополнительных настроек NUMA-привязки.
3.  **Контейнеризация:** `app-containers/docker` с `app-containers/nvidia-container-toolkit`. Обеспечивает проброс скомпилированных Triton-ядер из хост-системы в изолированное окружение SGLang.

## 5. Обновление и запуск системы

После применения конфигурации выполняется полная пересборка дерева пакетов:
`emerge --ask --verbose --update --deep --newuse @world`

Запуск контейнера SGLang выполняется с распределением памяти NUMA для равномерной нагрузки по всем модулям:
`numactl --interleave=all docker compose up -d`
