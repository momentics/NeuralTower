# Инженерная записка: GPU Watchdog

## Проблема

В системе используются два блока питания Corsair HX1500i. Ведомый БП питает мезонин 2 (GPU 2 и 3) и помпы системы жидкостного охлаждения. Если Add2PSU не сработал или ведомый БП вышел из строя, GPU 2 и 3 станут недоступны, а помпы не запустятся. Без защиты это приводит к:

- Запуску vLLM/SGLang с неполной топологией GPU (конвейер PP=2 не соберётся, модели класса 70B+ не запустятся);
- Перегреву GPU на мезонине 1 из-за остановки циркуляции теплоносителя.

## Решение

Два уровня защиты, встроенные в docker-compose.

### Startup Check (`gpu_watchdog.sh`)

Запускается первым сервисом через контейнер `gpu-check`. Выполняет запрос к `nvidia-smi` и ждёт появления всех четырёх GPU — до пяти попыток с интервалом в 30 секунд. Если обнаружено меньше четырёх GPU, скрипт завершается с кодом 1, и vLLM/SGLang не стартует. Полный лог пишется в `/var/log/neural_tower_gpu_check.log`.

### Watchdog (`gpu_watchdog_loop.sh`)

Фоновый контейнер `gpu-watchdog`. Каждые 10 секунд проверяет количество доступных GPU. При потере любого из них:

- логирование пропавших GPU и дампа `dmesg`;
- остановка контейнеров с рабочими нагрузками (`docker stop` для vLLM и SGLang);
- однократный shutdown — маркер-файл предотвращает повторное срабатывание.

## Логи

| Файл | Описание |
| --- | --- |
| `/var/log/neural_tower_gpu_check.log` | Startup Check: результат и причина блокировки запуска |
| `/var/log/neural_tower_gpu_watchdog.log` | Watchdog: события, остановка контейнеров, состояние GPU |

## Ограничения

Watchdog останавливает контейнеры с рабочими нагрузками, но не обесточивает систему. После срабатывания требуется физическая диагностика и перезагрузка.
