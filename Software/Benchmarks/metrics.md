# Метрики производительности NeuralTower

Настоящий перечень метрик предназначен для проведения сравнительного анализа и валидации различных программных конфигураций (движков инференса, квантования, методов спекулятивного декодирования и стратегий виртуализации памяти) при фиксированном аппаратном составе.

## 1. Метрики эффективности генерации на уровне языковой модели

* **Время до вывода первого токена (Time to First Token, TTFT)**  
    *Единица измерения:* Секунды / Миллисекунды.  
    *Описание:* Интервал времени от момента получения запроса сервером до момента генерации самого первого слова (токена) ответа. Данная метрика напрямую отражает скорость выполнения фазы первичной обработки контекста (Prefill). Ключевой показатель для оценки эффективности поблочной обработки текста (Chunked Prefill).

* **Задержка между токенами (Inter-Token Latency, ITL)**  
    *Единица измерения:* Миллисекунды.  
    *Описание:* Среднее время, затрачиваемое моделью на генерацию каждого последующего токена после вывода первого. Метрика изолированно измеряет скорость фазы пошагового декодирования (Decode). Позволяет в абсолютных значениях оценить прирост производительности от применения алгоритмов спекулятивного декодирования (MTP, EAGLE, Medusa).

* **Скорость генерации на одну последовательность (Single-Stream Throughput)**  
    *Единица измерения:* Токены в секунду (t/s).  
    *Описание:* Количество текстовых токенов, генерируемых моделью для одного изолированного пользователя за одну секунду. Рассчитывается как отношение общего количества выведенных токенов к полному времени генерации (за вычетом времени обработки контекста).

* **Суммарная пропускная способность системы (System Throughput)**  
    *Единица измерения:* Суммарное количество токенов в секунду по всем потокам.  
    *Описание:* Совокупный объем текстовой информации, обрабатываемый и генерируемый сервером при одновременной параллельной работе нескольких агентов или пользователей. Главный критерий оценки эффективности планировщика при динамическом пакетировании запросов (Continuous Batching).

## 2. Метрики подсистемы кэширования контекста

* **Коэффициент попадания в кэш контекста (Context Cache Hit Rate)**  
    *Единица измерения:* Проценты (%).  
    *Описание:* Доля запросов (или частей длинных промптов), для которых готовые математические ключи и значения (KV-кэш) были успешно найдены в памяти и переиспользованы без повторного вычисления на графических процессорах. Измеряется отдельно для каждого уровня иерархии: оперативная память видеокарт (VRAM), системная память хоста (RAM), твердотельный накопитель (Intel Optane).

* **Коэффициент промаха кэша (Context Cache Miss Rate)**  
    *Единица измерения:* Проценты (%).  
    *Описание:* Доля запросов, для которых потребовался полный повторный математический просчет всей истории диалога на вычислительных ядрах из-за вытеснения данных политиками устаревания (LRU).

* **Задержка извлечения холодного контекста (Cache Retrieval Latency)**  
    *Единица измерения:* Секунды.  
    *Описание:* Время, затрачиваемое подсистемой хранения на чтение, деквантование и загрузку бинарных файлов KV-кэша из иерархических слоев (с Intel Optane через системную память в видеопамять) при повторном обращении кодинг-агента к ранее обработанному крупному проекту.

* **Скорость вытеснения кэша (Cache Eviction Rate)**  
    *Единица измерения:* МБ/с / Количество сессий в минуту.  
    *Описание:* Интенсивность удаления фоновым потоком-демоном старых файлов контекста с твердотельного накопителя при достижении установленных лимитов емкости. Позволяет оценить накладные расходы операционной системы на выполнение файловых операций.

## 3. Метрики утилизации аппаратных ресурсов на уровне телеметрии железа

* **Коэффициент вычислительной загрузки графических процессоров (GPU Вычисления)**  
    *Единица измерения:* Проценты (%).  
    *Описание:* Плотность утилизации тензорных и потоковых ядер видеокарт. Падение этого показателя ниже 80% в моменты обработки контекста сигнализирует о наличии простоев (пузырей) в конвейере параллелизма или о задержках ввода-вывода на стороне дисковой подсистемы.

* **Объем распределенной видеопамяти (VRAM Allocation)**  
    *Единица измерения:*  ГБ.  
    *Описание:* Динамика потребления памяти HBM2 на каждой из четырех карт. Разделяется на статическую область (веса модели) и динамическую область (страницы кэша и рабочие тензоры активаций). Используется для поиска пиковых утечек памяти (Out-of-Memory) при подборе оптимального размера чанка.

* **Пропускная способность межпроцессорного интерфейса (NVLink Bandwidth)**  
    *Единица измерения:* ГБ/с.  
    *Описание:* Скорость обмена градиентами и активациями между видеокартами, объединенными попарно в рамках одного мезонина. Измеряет интенсивность выполнения коллективных операций синхронизации матриц (All-Reduce) на уровне тензорного параллелизма (`TP=2`).

* **Пропускная способность системной шины (PCIe Bandwidth via PLX)**  
    *Единица измерения:* ГБ/с.  
    *Описание:* Объем данных, передаваемый через коммутаторы PLX по линиям PCI Express. Фиксирует нагрузку на интерфейс в двух критических точках: передача тензоров между стадиями конвейерного параллелизма (`PP=2` между мезонинами) и асинхронный сброс/чтение страниц кэша контекста при обмене с Intel Optane.

* **Потребление мощности (Power Consumption)**  
    *Единица измерения:* Ватт (W).  
    *Описание:* Суммарная мощность, потребляемая сервером и отдельные GPU/ CPU.

* **Температура GPU / CPU**  
    *Единица измерения:* Градус Цельсия (°C).  
    *Описание:* Текущая температура вычислительных устройств.

* **Глубина очереди запросов (Request Queue Depth)**  
    *Единица измерения:* Штуки.  
    *Описание:* Число запросов, ожидающих обработки в очереди планировщика.

## 4. Интегральные системные метрики на уровне сквозного анализа

* **Стабильность времени отклика (Latency Jitter)**  
    *Единица измерения:* Коэффициент вариации / Стандартное отклонение.  
    *Описание:* Степень разброса времени генерации ответов на идентичные по длине запросы. Высокий показатель свидетельствует о непредсказуемой работе контроллеров памяти хоста или о конфликтах блокировок при одновременном обращении нескольких процессов к одному накопителю.

* **Энергетическая эффективность инференса (Performance-per-Watt)**  
    *Единица измерения:* Количество сгенерированных токенов на один потраченный Ватт-час.  
    *Описание:* Интегральный показатель, оценивающий аппаратную экономичность программной конфигурации. Учитывая жесткие ограничения по питанию серверной платформы, оптимизация параметров пакетирования и чанков должна приводить к максимальной утилизации процессорных ядер в рамках выделенного теплопакета (TDP).
