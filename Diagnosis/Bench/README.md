# Методология и инструмент плотного тестирования когнитивных возможностей на сверхдлинных контекстах (NeuralTower Long-Context Benchmark)

Тестовый стенд разработан специально для оценки глубины удержания контекста, логического мышления и извлечения связанных фактов большими языковыми моделями (на примере **Qwen/Qwen3.6-27B** и её квантованных версий). Тестирование адаптировано под аппаратные особенности и ограничения **NeuralTower** (4x NVIDIA Tesla V100 SXM2 32GB, 128GB HBM2, шина PCIe 3.0 / SlimSAS, движок инференса `1Cat-vLLM` / `vLLM`).

---

## 1. Требования к тестированию NeuralTower

### Программные требования

* Наличие установленной библиотеки `transformers` (для токенизации) и `vLLM` / `1Cat-vLLM` с поддержкой архитектуры Volta (`sm_70`).
* Корректная конфигурация RoPE (Rotary Position Embedding) в движке инференса для работы с контекстами до 1024к токенов.

```bash
pip install transformers torch sentencepiece

```

## 2. Методика и метод тестирования

Вместо классического метода "Needle in a Haystack", проверяющего только память, применяется метод Logical Multi-hop Context Padding.

### Суть метода

1. **Шумовое наполнение**: Контекст заполняется реальным фоновым текстом (техническая документация, системные логи, исходный код) до строго заданного объема в токенах.
2. **Внедрение когнитивного триггера**: В массив «шума» внедряется микро-задача («целевой фрагмент»), содержащая скрытое логическое противоречие, распределенное по тексту, или сложную многошаговую зависимость.
3. **Позиционное сканирование**: Тест-кейс для каждого объема генерируется в трех позициях целевого фрагмента относительно длины контекста для выявления эффекта «потери внимания в середине» (*Lost in the Middle*):
   * **Beginning** (5% от начала)
   * **Middle** (50% — геометрический центр)
   * **End** (95% от начала, перед финальной инструкцией)

### Плотная сетка тестирования

Для исключения «слепых зон» и построения плавного физического графика деградации, тест выполняется **строго по возрастанию** со следующим плотным шагом (в токенах):

* **2k, 4k, 8k, 16k** — зона микроконтекстов.
* **32k, 64k, 96k, 128k** — базовая зона стабильности.
* **160k, 192k, 224k, 256k** — граница заполнения VRAM и оценки эффективности шины SlimSAS.
* **320k, 384k, 448k, 512k** — зона тяжелой экстраполяции внимания и работы кастомного ML-стека.
* **640k, 768k, 896k, 1024k** — экстремальный предел платформы (1 миллион токенов).

## 3. Процесс работы

Эксперимент разделен на три последовательных этапа:

### Этап 1: Генерация артефактов

Запуск скрипта `generate_benchmarks.py`. Скрипт инициализирует оригинальный токенизатор целевой модели, прецизионно рассчитывает бюджет токенов для каждой точки сетки, собирает текстовые пакеты с внедренной логической задачей в трех позициях и сохраняет их в JSON-файлы в директорию `./neural_tower_dense_benchmarks`.

### Этап 2: Автоматизированный инференс

Управляющий скрипт поочередно считывает сгенерированные файлы строго по возрастанию объема контекста и отправляет их на локальный API-эндпоинт `vLLM`. Скрипт логирует ответ модели, а также системные метрики: время до первого токена (TTFT), скорость генерации (Tokens Per Second) и объем утилизации VRAM. 
*При возникновении аппаратной ошибки Out-Of-Memory (OOM) процесс останавливается, фиксируя физический предел конфигурации.*

### Этап 3: Валидация и Анализ

Полученные ответы проверяются на соответствие затребованному формату JSON и корректность логических выводов (метрика Accuracy / F1 для рассуждений).

## 4. Результаты

### Промежуточные результаты (Log-файлы)

В процессе выполнения тестов формируется JSON-массив результатов для каждой точки. Пример структуры записи:

```json
{
  "context_size": "192k",
  "position": "middle",
  "metrics": {
    "ttft_seconds": 14.2,
    "tokens_per_second": 22.4,
    "vram_allocated_gb": 104.5
  },
  "model_response": {
    "conflict_detected": true,
    "root_cause": "NVIDIA driver 580.12 requires 64-bit MMIO base address, but ASUS X99-E WS BIOS forces 32-bit BAR allocation with >2 SXM2 devices active."
  },
  "score": 1.0
}
```

### Финальные результаты

На основе собранных логов строятся три ключевых графика:

1. **Когнитивная точность (Y: Accuracy, X: Context Size)**: Три линии (Beginning, Middle, End), наглядно показывающие, в какой точке объема и в какой позиции контекста модель начинает терять причинно-следственные связи.
2. **График задержки (Y: TTFT, X: Context Size)**: Демонстрирует масштабируемость фазы Prefill на архитектуре Volta и влияние межпроцессорного обмена через PCIe 3.0.
3. **Физическая емкость**: Точная отметка объема контекста, при которой текущая квантованная версия модели вызывает падение инференс-движка по нехватке памяти.
