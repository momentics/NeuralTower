# Диагностика NVLink для TP

## 1. Диагностика в операционной системе Linux

Система Linux предоставляет наиболее полную программную поддержку для высокопроизводительных вычислений распределенного типа благодаря встроенной поддержке библиотеки распределенного обучения NVIDIA Collective Communications Library (NCCL).

### 1.1. Проверка физической и программной схемы соединений

Перед запуском вычислений необходимо убедиться, что графические ускорители связаны мостом NVLink на аппаратном и драйверном уровнях.

Выполните команду в терминале:

```bash
nvidia-smi topo -m
```

**Интерпретация таблицы соединений:**

* **`NV#`** (например, `NV2`, `NV4`): Графические ускорители успешно соединены через указанное количество линий NVLink. Система готова к аппаратному ускорению межпроцессорного обмена.
* **`PHB` / `NODE` / `SYS`**: Соединение NVLink отсутствует или не распознано. Обмен данными принудительно осуществляется через системную шину PCI Express или оперативную память системы.

### 1.2. Контроль загруженности каналов в реальном времени

Чтобы отличать поток данных параллельных вычислений от системного обмена, запустите циклическое выполнение процесса генерации в `llama.cpp` и параллельно отслеживайте показания счетчиков производительности.

**Проверка состояния портов NVLink:**

```bash
watch -n 1 nvidia-smi nvlink --status
```

*Во время вычислений состояние портов (`Link Status`) должно иметь значение `Active` (Активен).*

**Анализ пропускной способности через инструменты мониторинга драйвера:**

```bash
nvidia-smi dmon -s np
```

**Критерии корректной работы:**

1. В столбцах группы **`nvlk`** (пропускная способность NVLink) фиксируется непрерывный поток данных объемом в несколько гигабайт в секунду на протяжении всего цикла генерации.
2. В столбцах группы **`pci`** (поток данных шины PCI Express) высокая активность наблюдается исключительно в момент начала работы и загрузки весов модели в видеопамять. Во время непосредственного вывода текста значения загруженности шины PCI Express должны стремиться к нулю.

## 2. Диагностика в операционной системе Windows 10

Реализация параллельных вычислений в среде Windows 10 имеет ряд архитектурных ограничений. Основная сложность заключается в отсутствии официальной поддержки библиотеки NCCL для данной платформы. Вследствие этого программная библиотека `llama.cpp` вынуждена использовать базовые механизмы CUDA Peer-to-Peer (P2P), эффективная работа которых требует специальной настройки графической подсистемы.

### 2.1. Перевод графических ускорителей в режим вычислений (TCC)

По умолчанию в Windows 10 для всех графических ускорителей применяется модель драйверов WDDM (Windows Display Driver Model), предназначенная для вывода графического интерфейса системы. Данный режим блокирует эффективный прямой доступ между устройствами (P2P) и препятствует активации NVLink для ускорителей класса Tesla (включая форм-фактор SXM2).

Для перевода ускорителей в вычислительный режим **TCC (Tesla Compute Cluster)** запустите командную строку или консоль PowerShell от имени администратора и выполните:

```cmd
nvidia-smi -g 0 -dm 1
nvidia-smi -g 1 -dm 1
```

*После успешного выполнения команд необходимо перезагрузить систему.*

### 2.2. Проверка схемы соединений и доступности P2P

После перезагрузки убедитесь, что режим TCC активен, а таблица соединений определила межкомпонентные связи:

```cmd
nvidia-smi topo -m
```

Значение на пересечении идентификаторов графических ускорителей должно измениться со статуса общего системного канала на статус прямого аппаратного подключения (`NV#`).

### 2.3. Проверочный тест пропускной способности (Тест P2P)

Для проверки фактической скорости обмена данными без участия внешнего программного обеспечения используйте специализированную утилиту тестирования из состава CUDA Toolkit (`p2pBandwidthLatencyTest`).

Перейдите в каталог скомпилированных примеров CUDA и запустите программу:

```cmd
p2pBandwidthLatencyTest.exe
```

**Анализ результатов измерения:**

* **Скорость обмена > 25–30 Гбайт/с:** Передача данных успешно организуется через аппаратный мост NVLink.
* **Скорость обмена порядка 10–12 Гбайт/с (для PCI Express 3.0 x16):** Архитектура NVLink не задействована. Данные пересылаются по системной шине PCI Express, что подтверждает наличие проблемы в конфигурации или компиляции программы.

### 2.4. Визуальный контроль через Диспетчер задач Windows

Ввиду того, что консольная утилита `nvidia-smi dmon` в среде Windows накладывает ограничения на вывод счетчиков NVLink, для быстрой диагностики допускается использование штатного Диспетчера задач (вкладка "Производительность", разделы графических процессоров):

1. **Признак работы через PCI Express (Некорректно):** Графики счетчиков **`Copy`** или **`PCIe Link Utilization`** на обоих ускорителях непрерывно загружены в процессе генерации каждого отдельного слова. Это свидетельствует об отсутствии прямой связи.
2. **Признак работы через NVLink (Корректно):** На протяжении всего цикла вывода текста графики `Copy` и загруженности PCI Express остаются в статичном нулевом положении. При этом графики вычислительных ядер (**`Compute_0`** или **`CUDA`**) демонстрируют высокую и синхронную загрузку.
